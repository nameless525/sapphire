# lavapipe's differences from the counts table (M5 X4): the rows where CI's lane, on lavapipe on x86-64 Linux,
# counts differently from tests/counts/district-ci.txt, which an M5's Metal (aarch64) takes. The lane holds each
# walk to the table's figure plus the difference below (`sapphire_testkit counts --differences`); every other row
# to the table's. A line naming a walk or row the table doesn't hold, a difference of zero, or a line with no
# reason above it fails, so the file can't rot (sapphire_testkit::counts::differences).
#
# Why the two differ: which of the district's people stand. The crowd stands the people of the cells nearest the
# focus by ring around the focus's own cell, `floor(focus / 32 m)` (sapphire_stage/src/scene/ambient.rs
# `choose_ambient`), and the tour's camera walks the avenue on x = 0, which is a cell edge. On an M5 its eye's x is
# -1.6e-6, the residue of the orbit camera's `yaw.sin()` (sapphire_stage/src/orbit.rs `OrbitCamera::eye`), so
# its own cell is the one west of the edge; on lavapipe it is the one east of it. Every ring then differs, so a
# different set of people stands (the same number: `ambient_spawned` agrees on every frame) for as long as the
# camera stays on that line, and the same again a lap later. Proved on an M5: taking the focus's x as its
# magnitude on that line (one sign flip of a residue of 1.6e-6) makes all four desktop walks' traces equal
# lavapipe's on all 3,720 frames in every column, and their counts.txt equal lavapipe's on every row. Which of x86's
# operations leaves a non-negative residue (the sine, or the yaw it is taken of) is not proved. Nothing else
# differs: the camera's path, every static draw and every shadow and cascade row hold the table's figure on both,
# and each machine draws and culls correctly the crowd it chose (results identical across architectures are a
# non-goal, sapphire_math/src/det.rs, and this is a last-bit difference that a floor turns into a choice).
#
# A change that moves a row the same on both machines is written in the table alone. Refresh this file from CI's
# artifacts (each `scale-lane-<walk>` folder holds the run's counts.txt), walking nothing:
#   sapphire_testkit counts --table tests/counts/district-ci.txt \
#     --differences tests/counts/district-ci-vulkan-lavapipe.txt --refresh <folder>...
# It keeps each line's reason, and writes a new difference under a placeholder that fails until it has one.
#
# Bootstrapped from the scheduled run 43941132946 at f4efa213e (the lane's first); `animation jobs` added from
# #416's first run, `pipelines set` from its second, whose per-frame traces (`<walk>.csv` beside each log) found
# the cause above. The walks' fixed worker count (`--compute-threads 3`) takes the machine out of `animation jobs`:
# what it leaves is the crowd's, so it is in the second block.
