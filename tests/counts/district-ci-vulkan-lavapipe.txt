# lavapipe's differences from the counts table (M5 X4): the rows where CI's lane, on lavapipe on x86-64 Linux,
# counts differently from tests/counts/district-ci.txt, which an M5's Metal (aarch64) takes. The lane holds each
# walk to the table's figure plus the difference below (`sapphire_testkit counts --differences`); every other row
# to the table's. A line naming a walk or row the table doesn't hold, a difference of zero, or a line with no
# reason above it fails, so the file can't rot (sapphire_testkit::counts::differences).
#
# Why the two differ: results identical across architectures are a non-goal (sapphire_math/src/det.rs). glam's
# SIMD types sum and normalize in another order on SSE2 than on NEON, and presentation code calls the platform's
# libm (glibc against Apple's), so the last bit of a crowd member's place, heading or posed bounds differs, and the
# crowd's walk, integrating its heading step by step, grows one such bit into a character on the other side of a
# frustum plane now and then. The camera and every static draw agree: draws considered, level 0 and every shadow
# and cascade row hold the table's figure on both.
#
# A change that moves a row the same on both machines is written in the table alone. Refresh this file from CI's
# artifacts (each `scale-lane-<walk>` folder holds the run's counts.txt), walking nothing:
#   sapphire_testkit counts --table tests/counts/district-ci.txt \
#     --differences tests/counts/district-ci-vulkan-lavapipe.txt --refresh <folder>...
# It keeps each line's reason, and writes a new difference under a placeholder that fails until it has one.
#
# Bootstrapped from the scheduled run 43941132946 at f4efa213e (the lane's first). Not here, on purpose:
# `animation jobs`, which the walks' fixed worker count (`--compute-threads 3`) makes the same on both; and
# `pipelines set`, +82 on every desktop walk, which no reason explains yet (the walks log `pipelines set by pass`
# beside their rows to find it), so the lane fails on it until it is explained.
